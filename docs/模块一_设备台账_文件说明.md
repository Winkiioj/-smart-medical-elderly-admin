## 一、新增文件清单（11 个）

### 1.1 后端 — Entity 层（2 个）

| 文件 | 作用 | 映射表 |
|------|------|------|
| `entity/Device.java` | 设备台账实体。17个字段：id, deviceNo(编号), deviceName(名称), deviceType(类型), brand(品牌), model(型号), community(所属社区), elderlyId(关联老人，可空), status(1在线/2离线/3维修中/4已报废), buyDate(购置日), warrantyEnd(保修截止), lastReportTime(最后心跳), remark(备注), createBy(创建人), createTime, updateTime | `device` |
| `entity/DeviceMonitorLog.java` | 设备监控日志实体。7个字段：id, deviceId(关联设备), eventType(1上线/2离线/3数据上报/4状态变更), oldStatus(变更前状态), newStatus(变更后状态), message(描述), createTime | `device_monitor_log` |

**共同特征：**
- 使用 `@Data`（Lombok 自动生成 getter/setter）
- 使用 `@TableName("表名")` 映射数据库表
- 使用 `@TableId(type = IdType.AUTO)` 标记自增主键
- 字段名驼峰命名，自动映射数据库下划线字段

### 1.2 后端 — Mapper 层（3 个）

| 文件 | 作用 |
|------|------|
| `mapper/DeviceMapper.java` | 设备台账数据访问接口，继承 `BaseMapper<Device>`（自带 insert/update/delete/selectById 等） |
| `mapper/DeviceMonitorLogMapper.java` | 设备日志数据访问接口，继承 `BaseMapper<DeviceMonitorLog>` |
| `resources/mapper/DeviceMapper.xml` | DeviceMapper 的动态 SQL 补充（MyBatis XML） |

**DeviceMapper 自定义方法：**

| 方法 | 返回 | 说明 |
|------|------|------|
| `selectPage(page, keyword, deviceType, status, community)` | `IPage<Device>` | 多条件分页查询。keyword 模糊匹配设备编号/名称；deviceType/status/community 精确匹配。SQL 写在 DeviceMapper.xml 中 |
| `selectByDeviceNo(deviceNo)` | `Device` | 按设备编号精确查询，用于录入时查重 |
| `countByStatus(status)` | `int` | 按状态统计数量，用于 Dashboard 数字卡片 |
| `selectByCommunity(community)` | `List<Device>` | 按社区查询设备列表 |

**DeviceMonitorLogMapper 自定义方法：**

| 方法 | 返回 | 说明 |
|------|------|------|
| `selectByDeviceId(deviceId, limit)` | `List<DeviceMonitorLog>` | 查询某设备最近 N 条日志 |
| `selectHeartbeats(deviceId, startTime, endTime)` | `List<DeviceMonitorLog>` | 查询某设备在指定时间范围的心跳记录（eventType IN 1,2） |

### 1.3 后端 — Service 层（4 个）

| 文件 | 作用 |
|------|------|
| `service/DeviceService.java` | 设备台账业务接口，继承 `IService<Device>` |
| `service/impl/DeviceServiceImpl.java` | 设备台账业务实现 |
| `service/DeviceMonitorLogService.java` | 设备日志业务接口，继承 `IService<DeviceMonitorLog>` |
| `service/impl/DeviceMonitorLogServiceImpl.java` | 设备日志业务实现 |

**DeviceService 方法：**

| 方法签名 | 返回 | 说明 |
|------|------|------|
| `pageList(pageNo, pageSize, keyword, deviceType, status, community)` | `CommonResult` | 分页查询。调用 `DeviceMapper.selectPage`，返回 `CommonResult.success(records, total)` |
| `getDetail(id)` | `CommonResult` | 设备详情。404 时返回 `CommonResult.error(404, "设备不存在")` |
| `add(device, operatorId)` | `CommonResult` | 录入设备。自动生成编号 `DEV-yyyyMMdd-序号`；设置初始状态=离线(2)；记录创建人；写操作日志 |
| `updateInfo(device)` | `CommonResult` | 编辑设备信息。乐观锁校验 `updateTime`（不一致返回 400）；编号不允许修改；记录操作日志 |
| `updateStatus(id, newStatus, operatorId)` | `CommonResult` | 状态变更。校验状态值范围(1-4)；报废(4)为终态不可再变更；记录 from→to 操作日志 |
| `countByStatus(status)` | `int` | 按状态统计数量（供 Controller stats 用） |

**DeviceServiceImpl 关键逻辑：**

| 逻辑 | 说明 |
|------|------|
| 编号自动生成 | `DEV-{yyyyMMdd}-{当日序号3位}`。查询当天已录入数，序号=count+1，格式化为3位 |
| 乐观锁 | 编辑时比较前端传入的 `updateTime` 与数据库的 `updateTime`，不一致则拒绝 |
| 状态校验 | 更新状态时校验 1-4 范围、报废终态不可逆 |
| 操作日志 | 所有写操作(录入/编辑/状态变更)自动调用 `deviceMonitorLogService.logEvent()` 记录 |

**DeviceMonitorLogService 方法：**

| 方法签名 | 返回 | 说明 |
|------|------|------|
| `getRecentLogs(deviceId, limit)` | `List<DeviceMonitorLog>` | 查最近 N 条日志 |
| `logEvent(deviceId, eventType, oldStatus, newStatus, message)` | `void` | 记录一条操作日志。构建 DeviceMonitorLog 对象并 insert |

## 三、数据流示意

```
用户操作 DeviceManage.vue
    │
    ├── 查询设备列表
    │   └── api/device.js → GET /api/device/page
    │       → Controller.page()
    │           → Service.pageList()
    │               → Mapper.selectPage() → DeviceMapper.xml 动态SQL
    │                   → MySQL device 表
    │
    ├── 录入设备
    │   └── api/device.js → POST /api/device/add
    │       → Controller.add()
    │           → Service.add()
    │               → 生成编号 DEV-20260717-001
    │               → Mapper.insert()
    │               → MonitorLogService.logEvent("设备录入")
    │
    ├── 编辑设备
    │   └── api/device.js → PUT /api/device/update
    │       → Controller.update()
    │           → Service.updateInfo()
    │               → 乐观锁校验 updateTime
    │               → Mapper.updateById()
    │               → MonitorLogService.logEvent("设备信息编辑")
    │
    └── 状态变更
        └── api/device.js → PUT /api/device/status/{id}
            → Controller.updateStatus()
                → Service.updateStatus()
                    → 校验状态值(1-4)、报废终态不可逆
                    → Mapper.updateById()
                    → MonitorLogService.logEvent("状态变更: 离线→在线")
```

## 四、开发时记录的问题与解决

| # | 问题 | 原因 | 解决 |
|------|------|------|------|
| 1 | 启动报 GSSAPI 认证错误 | MariaDB JDBC 驱动与远程数据库认证协议不兼容 | 切回 MySQL 驱动 + 修改为远程数据库 IP |
| 2 | `@NoToken` 加在类上不生效 | 注解的 `@Target` 仅为 `METHOD` | 改为每个方法加 `@NoToken` |
| 3 | Spring Security 拦截请求 | 默认 Security 配置要求全部认证 | 新增 `SecurityConfig.java` 放行 `/api/**` |
| 4 | `selectCount` 返回 `Long` 编译错误 | `int count = (int) mapper.selectCount()` | 改用 `.intValue()` |
| 5 | npm 安装慢 | 默认源在国外 | `npm config set registry https://registry.npmmirror.com` |
| 6 | vite 启动 native binding 错误 | npm 安装损坏 | 删除 node_modules + package-lock.json 重装 |
| 7 | Controller 传参不规范 | `updateStatus(Device)` 创建假对象 | 改为 `updateStatus(Long id, Integer newStatus, Long operatorId)` |
