## 一、技术栈选型

### 1.1 总体技术架构

```
┌──────────────────────────────────────────────────────────┐
│                    前端展示层 (浏览器)                      │
│   Vue 3 + Vite + Element Plus + ECharts + Axios           │
├──────────────────────────────────────────────────────────┤
│                    后端服务层 (服务器)                      │
│   Spring Boot 3.x + MyBatisPlus + Spring Security + JWT   │
├──────────────────────────────────────────────────────────┤
│                    数据存储层                              │
│   MySQL 8.0 + Redis 7.x                                   │
├──────────────────────────────────────────────────────────┤
│                    部署层                                  │
│   Nginx + Docker + Linux (CentOS/Ubuntu)                  │
└──────────────────────────────────────────────────────────┘
```

### 1.2 技术选型明细

| 层次 | 技术 | 版本 | 选型理由 |
|------|------|------|----------|
| **前端框架** | Vue 3 | 3.4+ | 培训课程教授 Vue，学习成本低；组合式 API 开发效率高 |
| **构建工具** | Vite | 5.x | 比 Webpack 快 10 倍以上的热更新，7 天开发分秒必争 |
| **UI 组件库** | Element Plus | 2.x | 企业级后台管理系统首选，表格/表单/弹窗开箱即用 |
| **图表库** | ECharts | 5.x | Dashboard 和报表展示必备，百度出品文档丰富 |
| **后端框架** | Spring Boot | 3.4.x | 培训核心教授内容，自动配置减少 80% 样板代码 |
| **ORM 框架** | MyBatisPlus | 3.5.x | 培训课程教授；单表 CRUD 无需手写 SQL，复杂查询用 XML |
| **权限认证** | Spring Security + JWT | 最新稳定版 | RBAC 权限控制 + 无状态 Token 认证 |
| **数据库** | MySQL | 8.0 | 关系型数据库，医养数据（老人档案/健康报告）结构化存储 |
| **缓存** | Redis | 7.x | Dashboard 数据缓存 + 登录 Token 黑名单 |
| **API 文档** | Knife4j (Swagger) | 4.x | 接口自动生成文档，前后端联调利器 |
| **部署** | Nginx + Docker | 最新稳定版 | 前端静态资源代理 + 后端容器化部署 |

### 1.3 7 天内不引入的技术（故意砍掉）

| 不引入 | 原因 |
|--------|------|
| 微服务 / Spring Cloud | 7 天单体架构足够，微服务是过度设计 |
| RabbitMQ / Kafka | 异步消息队列暂时不需要，同步处理即可 |
| XXL-Job 定时任务 | 健康预警用 Spring @Scheduled 替代 |
| MongoDB | 只用到结构化数据，MySQL 全覆盖 |

## 二、架构分层设计

### 2.1 后端分层架构

```
┌─────────────────────────────────────┐
│   Controller 层 (接收 HTTP 请求)      │   @RestController
│   - UserController                  │   - 参数校验 (@Valid)
│   - ElderController                │   - 接口鉴权 (@PreAuthorize)
│   - WarningController              │   - 统一返回 Result<T>
│   - ReportController               │
│   - DashboardController            │
│   - DeviceController               │
│   - StatisticsController           │
└──────────────┬──────────────────────┘
               │ 调用
┌──────────────┴──────────────────────┐
│   Service 层 (业务逻辑)              │   @Service
│   - 数据校验 + 业务规则处理           │   - 事务管理 @Transactional
│   - 预警规则引擎                     │   - 审批工作流
│   - 报表计算逻辑                     │   - 评估打分算法
└──────────────┬──────────────────────┘
               │ 调用
┌──────────────┴──────────────────────┐
│   Mapper 层 (数据访问)               │   @Mapper
│   - MyBatisPlus BaseMapper          │   - 单表: LambdaQueryWrapper
│   - 复杂查询: XML SQL               │   - 多表: 手写 SQL + ResultMap
└──────────────┬──────────────────────┘
               │ JDBC
┌──────────────┴──────────────────────┐
│   MySQL 8.0 数据库                  │
└─────────────────────────────────────┘
```

|------|------|----------|----------|
| ① | 首页数据看板 | Dashboard 聚合数据接口 | Redis 缓存 + SQL 聚合查询 |
| ② | 系统消息通知 | 消息 CRUD + 已读/未读状态管理 | WebSocket 或轮询方案 |

| ④ | 家属信息管理 | 家属信息维护 + 关联老人 | 一对多关联查询 + 级联操作 |

        └─────────────────┘      └─────────────────┘      └─────────────────┘
             后端核心                  业务+可视化                  前端+交互

## 七、风险识别与应对

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|----------|
| Spring Security + JWT 配置耗时长 | 高 | 卡住 Day2 进度 | A 提前准备配置模板，Day1 就搭好 |
| 健康预警规则引擎设计过于复杂 | 中 | Day4 做不完 | 第一版只做"阈值预警"，不做复杂规则组合 |
| 大数据大屏前端开发超时 | 中 | Day5-6 压力大 | C 提供 ECharts 组件，B 只填充数据 |
| PDF 报告导出遇到兼容问题 | 中 | Day4-6 延期 | 优先用前端 HTML→PDF，后端方案兜底 |
| 前后端联调发现大量接口不一致 | 低 | Day6 返工 | Day1 定义好接口文档(Knife4j)，按文档开发 |
| 时间不够，部分模块做不完 | 高 | 答辩减分 | ⭐ 核心策略：Day3-5 优先保证"能演示的核心流程"，CRUD 功能完整即可 |
