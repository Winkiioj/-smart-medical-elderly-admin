> **选题编号：** 项目 #7（医疗板块 · 云端后台管理系统）  
> **核心三问：** 系统是干什么的？用户是谁？怎么使用？  
> **用途：** 团队头脑风暴基准文档，对齐全员对需求的理解

## 一、这个系统是干什么的？

### 一句话概括

**这是一个给社区养老机构使用的老人健康管理后台系统。**

### 它解决的核心痛点

社区养老机构管着几百上千位老人，每个老人每天有血压、血糖、心率等健康数据产生，数据超过正常范围需要有人及时处理，每个月还要出健康评估报告。靠 Excel + 微信群管这些事，迟早出问题。

这个系统做的事情就是把整个流程**数字化、自动化**：

```
老人入住建档 → 日常健康数据录入 → 自动预警异常 → 医生处理 → 随访跟踪 → 生成评估报告
```

### 四大功能板块

| 板块 | 干什么 | 举例 |
|------|--------|------|
| **档案管理** | 管"人" | 老人基本信息、家属联系人、健康史记录、老人账户 |
| **健康预警** | 管"风险" | 设定血压阈值规则 → 数据超标自动触发预警 → 医生处理跟踪 |
| **设备管理** | 管"设备" | 血压计/血糖仪/智能腕表的台账、在线状态监控、离线告警 |
| **数据决策** | 管"全局" | Dashboard 总览卡片、统计报表、数据大屏（给领导汇报用） |

### 它不是什么（系统边界）

明确系统边界，避免范围蔓延：

```
✅ 本系统做：               ❌ 本系统不做：
   - 后台管理 Web 端            - 给老人用的手机 App（那是项目 #8）
   - 老人档案 + 健康数据管理     - 在线问诊 / 即时通讯
   - 自动预警 + 处理流程         - 医院 HIS 系统对接
   - 设备台账 + 状态监控         - 医保结算
   - 统计报表 + 数据可视化       - 真实物联网设备对接（数据模拟即可）
```

## 二、用户画像是怎么样的？

系统有 **四类用户**，每个人登录后看到的界面和能做的事情完全不同，由 RBAC 权限控制。

---

### 用户角色 ① — 机构管理员

> 卫健委 / 平台最高管理者

```
典型人物：张主任，45岁，区卫健委信息科负责人

日常场景：
  打开电脑 → 看 Dashboard 总览 → 发现某社区预警处理率偏低 → 打电话督促

核心需求：
  - 查看各社区统计报表（全区老人数、设备在线率、预警处理率、随访完成率）
  - 跨社区数据对比，发现异常指标（如某社区预警处理率偏低）
  - 整理汇总数据，向上级卫健委汇报

技能水平：   会用浏览器，不需要懂技术
登录频率：   每天 1-2 次，每次 5-10 分钟
核心痛点：   管人管权限，需要一眼看到全局状态
```

---

### 用户角色 ② — 社区医生

> **核心用户，使用频率最高，系统 70% 的功能为他设计**

```
典型人物：李医生，32岁，社区全科医生，签约管理 200+ 位老人

日常场景（典型一天）：
  早上到岗 → 打开系统查看 Dashboard → 处理待办预警 →
  录入新来的老人档案 → 上午有老人来测血压血糖，录入数据 →
  下午安排 3 位随访（今天到期）→ 电话/上门随访 → 填写随访记录 →
  月末给重点老人出健康评估报告 → 导出 PDF

核心需求：
  - 老人档案：查/增/改，支持按姓名/身份证/社区/年龄段筛选
  - 健康数据：录入血压/血糖/心率/血氧/体重等指标
  - 预警处理：查看待处理预警 → 确认/联系家属 → 填写处理意见 → 完成
  - 随访管理：查看随访计划 → 执行随访 → 记录结果 → 设置下次随访
  - 评估报告：选择模板 → 逐项打分 → 生成综合评估 → 导出 PDF
  - 消息通知：接收预警推送、随访提醒、系统通知

技能水平：   日常办公软件水平
登录频率：   全天挂着，频繁操作
核心痛点：
  ① 老人太多记不住谁有什么病史 → 系统里搜索一查就出来
  ② 预警不及时容易出医疗事故 → 系统自动比对规则、实时推送
  ③ 月底写报告要翻一堆纸质记录 → 系统一键生成评估报告
```

---

### 用户角色 ③ — 设备管理员

> 负责智能健康设备的运维人员

```
典型人物：小王，26岁，养老机构内负责智能设备运维

日常场景：
  早上巡检 → 打开设备监控面板 → 看到 3 台设备离线（红灯）→
  去现场检查（电池没电/网络断开）→ 修好后设备恢复在线（绿灯）→
  新到一批智能腕表 → 录入设备台账（编号/类型/所属社区/分配老人）→
  旧设备报废 → 标记状态为"已报废"

核心需求：
  - 设备台账：设备 CRUD（编号/名称/类型/所属社区/当前状态）
  - 状态监控：设备在线面板（🟢在线 🟡待机 🔴离线）
  - 离线告警：设备超过 2 小时未上报数据 → 自动标记离线并告警
  - 状态流转：在线 → 离线 → 维修中 → 已报废

技能水平：   会简单操作电脑
登录频率：   每天巡检时使用
核心痛点：
  不知道哪些设备坏了 → 系统面板一目了然
  设备去向不清楚 → 系统记录每台设备当前的分配状态
```

---

### 用户角色 ④ — 社区管理员

> 社区养老机构 / 服务中心负责人

```
典型人物：陈院长，40岁，某社区养老服务中心负责人

日常场景：
  月底要交汇报材料 → 打开系统 → 查看本社区老人统计（数量/年龄分布/健康状况）→
  查看本月随访完成率和预警处理率 → 导出老人信息 Excel →
  导出预警记录 Excel → 汇总给上级

  新来了一位社区医生 → 录入医生信息并开通系统账号 →
  本周有3位新入住老人 → 为他们分配签约医生 →
  核查本月各医生随访完成情况 → 生成绩效报表

核心需求：
  - 管理本社区医生档案（增删改查、开通/禁用账号）
  - 为新入住老人分配签约医生
  - 查看本社区报表统计（老人分布、健康数据统计、随访完成率等）
  - 导出数据（Excel 格式）

技能水平：   会 Office
登录频率：   每周几次，月底频繁
核心痛点：
  新医生入职要手动记录信息容易遗漏 → 系统统一管理
  老人分配医生靠口头沟通容易出错 → 系统分配记录可追溯
  月底做汇报要数据 → 系统图表+导出直接可用
```

## 三、用户是怎么使用的？

这是系统**最核心的使用场景**，覆盖了 70% 的功能。

---

#### 早上 8:30 — 到岗查看 Dashboard

```
操作步骤：
  ① 打开浏览器 → 输入系统地址 → 看到登录页
  ② 输入账号密码 + 验证码 → 点击登录
  ③ 进入 Dashboard 首页，看到：
     ┌─────────────────────────────────────────┐
     │ 📊 我的工作台                            │
     ├─────────────────────────────────────────┤
     │ [238] 负责老人  [6] 本月新增  [96%] 在线率│  ← 数字卡片
     │ [5条] 待处理预警  [3条] 未读消息          │
     ├─────────────────────────────────────────┤
     │ 📈 近30天新增老人趋势图（折线图）          │
     │ 🍩 老人年龄分布（饼图）                   │
     │ ⚠️ 最新预警记录（前5条，红色高亮）         │
     └─────────────────────────────────────────┘

系统动作（后端）：
  - JWT Token 验证 → 解析用户角色 → 返回角色对应的菜单权限
  - Dashboard 数据从 Redis 缓存读取（每 30 分钟刷新一次）
  - 预警待处理数通过 COUNT 实时查询
```

### 权限与可见性

```
不同角色看到的数据范围：

机构管理员 ──→ 全区所有数据（全部社区、全部老人、全部设备）
社区医生   ──→ 自己签约的老人数据 + 全区预警（可查看） + 本人消息
设备管理员 ──→ 全部设备数据 + 设备告警
社区管理员 ──→ 本社区中的老人数据 + 本社区统计报表

权限粒度：
  - 菜单权限：不同角色看到不同的侧边栏菜单
  - 按钮权限：如"删除"按钮只对管理员开放
  - 数据权限：社区管理员只能查本社区数据
```

## 四、头脑风暴检查清单

团队讨论时，可以用以下问题来检验需求理解是否对齐：

```
□ 我们是否都同意系统是后台管理系统（不是 App、不是小程序）？
□ 我们是否都理解四类用户的区别和各自的核心需求？
□ 我们是否都同意"社区医生"是最核心的用户，功能设计优先围绕他展开？
□ 我们是否对"老人建档 → 健康录入 → 预警触发 → 医生处理 → 随访 → 评估报告"这条主流程没有分歧？
□ 我们是否同意设备数据用模拟方式（不做真实 IoT 对接）？
□ 我们是否同意 MVP 底线是：登录 → Dashboard → 老人档案 → 预警处理 这个链路可演示？
□ 还有哪些功能点我们对"做不做"有分歧？（记录下来，用 MoSCoW 优先级决策）
```
