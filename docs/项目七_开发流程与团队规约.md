## 二、团队分工模型（全栈开发制）

### 核心原则

> **每个人独立负责 1~2 条完整业务线，从数据库 → 后端 API → 前端页面，一条龙全栈交付。**

这样做的优势：
- 每个人都能讲清楚自己业务线的完整技术实现（答辩时老师会问）
- 避免"前端等后端接口、后端等前端页面"的耦合等待
- 个人实习报告有东西写，每人都有完整的全栈开发经历

### 分工方案（暂定，头脑风暴后可调整）

| 成员 | 角色 | 业务线 | 涉及模块 |
|:--:|------|------|------|
| **A** | 项目经理 | **认证授权线** + **数据看板线** | ①RBAC权限 ②用户登录/注册 ③数据看板Dashboard ④消息通知 ⑤老人账户管理 |
| **B** | 开发 | **老人管理线** + **健康预警线** | ①老人档案 ②家属信息 ③健康史 ④预警规则 ⑤预警记录 ⑥评估模板 ⑦报告生成 |

### 数据库设计注意事项

数据库设计是评审时老师重点看的，要求：
- E-R 图：实体框、属性椭圆、关系菱形，标注 1:N / N:M
- PDM：PowerDesigner 16.5 生成，表名/字段名/类型/主键/外键/索引全部标清楚
- DDL：导出后检查一遍，确保能在 MySQL 8.0 上直接运行
- **至少 10 张表**，覆盖你们 18 个模块的全部数据需求

**🔵 构建阶段 5 天节奏建议：**

```
Day 5 — 骨架日
  上午：A 搭后端骨架（Security+JWT+公共类+建表）
        B+C 搭前端骨架（路由+布局+登录页）
  下午：目标 —— 全栈链路跑通（登录→首页→一个最简单的CRUD）

Day 6 — 核心业务日
  上午：各自开发自己业务线的核心模块（最重要的那个）
  下午：联调已完成的模块，确保每人至少跑通 1 条完整业务线

Day 7 — 业务冲刺日
  全天：各自业务线的剩余模块开发
  傍晚：联调 + 修 Bug

Day 8 — 收尾+大屏日
  上午：各自开发自己业务线的辅助模块
  下午：Dashboard + 数据大屏开发（A+C 合作）
        前端页面 UI 精调

Day 9 — 测试+部署日
  上午：JUnit 测试补齐（目标 20+ 条，每人至少 6 条）
        全量联调，所有业务线串一遍
```

## 五、Git 分支策略

```
main                        ← 最终交付版本，受保护，只有 PM 可合并
  └── dev                   ← 开发主线，所有人合并到这里
       ├── feature/auth      ← A：认证授权线
       ├── feature/dashboard ← A：数据看板线
       ├── feature/elderly   ← B：老人档案线
       ├── feature/health    ← B：健康预警线
       ├── feature/device    ← C：设备管理线
       └── feature/report    ← C：报表统计线
```

**分支规范：**

| 规则 | 说明 |
|------|------|
| 分支命名 | `feature/<业务线>` 全小写，短横线连接 |
| 提交时机 | 功能完成一个小的可运行单元就提交，不要攒一整天 |
| 提交信息 | 中文描述，格式：`feat: 完成老人档案列表查询接口` / `fix: 修复JWT过期后不刷新的bug` |
| 合并流程 | 每个模块开发完 → 提 PR 到 dev → A 做 Code Review → 合并 |
| 每日同步 | 每天早上开工前 `git pull dev` 拉最新代码，避免冲突累积 |

## 七、接口契约规范

### 统一响应格式

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {},
  "total": 100
}
```

| 字段 | 说明 |
|------|------|
| `code` | 200 成功；4xx 客户端错误；5xx 服务端错误 |
| `msg` | 提示信息 |
| `data` | 返回数据（单个对象、数组或 null） |
| `total` | 分页查询时返回总条数，非分页时可省略 |

### 错误码枚举

```java
SUCCESS(200, "操作成功"),
BAD_REQUEST(400, "请求参数错误"),
UNAUTHORIZED(401, "未登录或Token已过期"),
FORBIDDEN(403, "无权限访问"),
NOT_FOUND(404, "资源不存在"),
INTERNAL_ERROR(500, "服务器内部错误");
```

### RESTful URL 约定

```
GET    /api/{resource}            # 分页列表
GET    /api/{resource}/{id}       # 详情
POST   /api/{resource}            # 新增
PUT    /api/{resource}/{id}       # 更新
DELETE /api/{resource}/{id}       # 删除
POST   /api/{resource}/batch      # 批量操作
```
